# Contributing to JMeter for QA

Thank you for your interest in contributing to **JMeter for QA Engineers**.

This project aims to provide a practical, beginner-friendly, and technically accurate learning resource for QA Engineers who want to learn Apache JMeter and performance engineering.

Contributions are welcome, including documentation improvements, examples, corrections, test plans, troubleshooting guides, and learning resources.

## 🧭 Before Contributing

Please make sure your contribution:

* Is relevant to QA, JMeter, API testing, or performance engineering.
* Adds practical value for learners.
* Uses clear and understandable technical language.
* Does not contain sensitive information or real credentials.
* Does not introduce unnecessary dependencies.
* Includes appropriate documentation when adding a new example or test plan.

## 🌿 Branching

Please create a separate branch for your contribution.

Examples:

```text
feature/api-performance-example
docs/correlation-guide
fix/incorrect-jmeter-example
```

Avoid making changes directly on `main` for substantial contributions.

## 📝 Commit Messages

Use clear, descriptive commit messages.

Examples:

```text
docs: add JMeter installation guide
feat: add API parameterization example
test: add authentication performance scenario
fix: correct JSON extractor example
docs: improve workload modeling documentation
```

## 🧪 Test Plans

When contributing a JMeter `.jmx` test plan:

* Clearly describe its purpose.
* Use meaningful component names.
* Avoid hard-coded credentials.
* Document required variables and test data.
* Include setup instructions.
* Ensure the test plan can be reproduced by another user.

## 🔐 Security

Never commit:

* Passwords
* API keys
* Access tokens
* Session tokens
* Private certificates
* Production credentials
* Personally identifiable information

Use example or placeholder values instead.

## 📚 Documentation Contributions

Documentation improvements are highly encouraged.

Examples include:

* Fixing technical inaccuracies
* Improving explanations
* Adding examples
* Adding diagrams
* Adding troubleshooting steps
* Improving grammar or readability

## 🤝 Pull Requests

Please provide a clear description of:

1. What you changed
2. Why you changed it
3. How you tested it
4. Any additional information contributors should know

Keep pull requests focused on a specific improvement whenever possible.

## 💡 Questions and Suggestions

If you find an issue, have a suggestion, or believe something is technically incorrect, please open an issue with enough context for others to understand and reproduce the problem.

Thank you for helping make JMeter for QA a better learning resource.
